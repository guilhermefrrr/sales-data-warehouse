Não consegui carregar o data.json automaticamente

Você abriu a versão leve (index.html). Ela não funciona com dois cliques, porque ela busca o data.json com fetch() e o navegador bloqueia isso em file://. Para abrir com dois cliques, use o index_standalone.html (1 arquivo só, já com os dados dentro). Para usar esta versão leve, abra com servidor / GitHub Pages, com o data.json na mesma pasta.

Privacidade & como atualizar

Removido do site de propósito: identificacao_comprador, ultimos_digitos_cartao e codigo_serie. O site mostra só agregados + vendas sem identificadores.

Como atualizar quando chegarem dados novos? O site guarda os dados em 2 lugares iguais: no arquivo data.json e numa cópia dentro deste index.html. Para não ficar com 2 versões diferentes, atualize os 2 juntos.

  1. Passo 1 — Gere o dump novo. No SSMS, gere um novo dump da Gold (Tasks > Generate Scripts) com as 5 tabelas: dim_evento, dim_maquinas, dim_produtos, fact_vendas, fact_pagamentos. Salve como script.sql.
  2. Passo 2 — Rode o programa que atualiza os 2 lugares. Você tem 2 jeitos, o resultado é o mesmo:

    Jeito A — no terminal: na pasta onde estão os arquivos, rode:
    python sql_to_json.py script.sql -o data.json --html index.html

    Jeito B — no Colab (sem terminal): suba os 3 arquivos (script.sql, sql_to_json.py e index.html) para o Colab, rode numa célula:
    !python sql_to_json.py script.sql -o data.json --html index.html
    e baixe de volta os 2 arquivos atualizados: data.json e index.html.
  3. Passo 3 — Por que 2 lugares? No GitHub Pages, o site lê o data.json. Abrindo com dois cliques, o navegador bloqueia essa leitura, então o site lê a cópia que está dentro do index.html. Se atualizar só um, um jeito de abrir vai mostrar dados novos e o outro, dados velhos.
  4. O que o programa faz sozinho: lê o script.sql, tira os campos sensíveis, cria o data.json novo e troca a cópia dentro do index.html. Você não precisa copiar e colar nada à mão.
